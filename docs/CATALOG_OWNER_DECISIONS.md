## Remaining Blockers

1. **Площадь/формат листа для 240 поверхностей.** Дать проверенные длину, ширину и площадь **для каждого продаваемого формата** либо доказанное правило на однородную группу с исключениями. Пока `1 sheet × area (м²) × price (₽/м²)` нельзя посчитать; соответствующие Cart/Checkout TASK не должны рассчитывать или принимать итоговую сумму. Текст двух «Калаката» из старого источника не является owner confirmation.
2. **20 товаров с диапазоном SOURCE PRICE.** Точная фиксированная цена/вариант (либо явное коммерческое правило расчёта с подтверждённой единицей) отсутствует; список ниже. Они входят в launch scope, но их fixed-price commerce остаётся BLOCKED.
3. **11 сопутствующих материалов.** Цифры цены подтверждены на дату, однако price unit, sale unit, minimum, step и применимость размеров/упаковки ещё не подтверждены. Правило `м² / 1 sheet / 1 sheet` к ним не применяется; Cart/Checkout для них BLOCKED до утверждения единицы и количества.
4. **Public slug collisions.** Две разные «Калаката» имеют одинаковый legacy slug `kalakata`. Также три разных карточки акрилового покрытия 3/5.4/10.7 кг имеют одинаковый усечённый legacy slug `finishnoe-pokritie-akrilovoe-dlya-gibkog`. Утвердить уникальные public slug или модель вариантов до выдачи Product Detail URL. Существующие два товара «Калаката» не сливать.
5. **Availability перед приёмом заказа.** Публичный статус скрыт, но ни для одного SKU пока нет назначенного `in_stock`/`on_order`. До checkout нужна политика, может ли SKU без статуса приниматься к заявке, и назначение доступности через Admin; не делать невидимый статус эквивалентом «в наличии».

**Не блокируют новую идентичность:** 20 расхождений старых DOM ID и URL ID (6 травертинов, 14 керамик) сохранены в [исходном evidence](CONTENT_FACTS.md#уточнения-и-расхождения) и [таблице конфликтов](CATALOG_OWNER_REVIEW.md#conflicts-requiring-owner-decision). У каждого из этих 20 теперь свой неизменяемый SKU, привязанный к URL ID. Повторная сверка старой платформы нужна только если появится конкретное расхождение контента/вариантов; не переименовывать SKU по DOM ID.

## Gate for future implementation

Подтверждение перечня и назначение SKU **не разрешают импорт 251 коммерчески готового товара**. До UI с расчётом `лист → м² → итог` и до Cart/Checkout требуются данные из блокеров 1–3; для Product Detail URL — блокер 4; для заявки с обещанием доступности — блокер 5. Товар с пустой fixed price/единицей/форматом должен оставаться в состоянии без вычисляемой цены и без приёма некорректного заказа. T008 остаётся BLOCKED до уточнения фактов, T009 не начинается.
